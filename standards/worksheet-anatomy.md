# Worksheet Anatomy

How a multi-part worksheet is laid out page by page. A worksheet is not left to flow; every page break is a decision. Space sizing is in `workspace-sizing.md`.

## 1. The intro is one full page of general information

The first page carries only what a student needs to understand the problems: definitions, the governing equations, and the instruction to choose a sign convention (never a stated convention; see `physics-language.md` section 5). It **never names the specific problem situation**.

If the intro spills onto a second page, trim its prose until it fits one page. Do not let it run over.

Wrong: an intro that opens "A ball is launched horizontally from a 20 m cliff at 8.0 m/s..."
Right: an intro that defines horizontal launch, lists the kinematic equations, and tells students to choose positive directions for x and y.

## 2. The situation is introduced in Part 1

The specific situation appears in Part 1, in its own stem. Part 1 is where the numbers first appear.

## 3. Every section starts at the top of a page

A part heading landing mid-page is a defect, even if everything fits.

## 4. A question never splits across a page

Stem, blank work space, and answer stay together on one page. On a test, each page starts with a whole problem.

## 5. Mechanics

```css
.qbox{break-inside:avoid}             /* stem + space + .ans, one unit */
h2{break-before:page}                 /* each section on a new page */
h2.first{break-before:auto}           /* except the first */
```

Wrap every question (stem, work space, answer) in a `.qbox`. A page that comes out nearly empty (a few percent fill) means an unbreakable block just missed fitting; cut prose elsewhere to buy the room, never work space.

## 6. What the print check can and cannot catch

An automated print check (such as printfit) measures each page's fill, overflow, figure sizing, and text scale. It catches content running off the page, missing figure heights, text that shrinks below a readable size, and pages with too much leftover space.

It **cannot** tell you that:

- a question's work space was orphaned onto the next page,
- a section heading landed halfway down a page,
- the intro named the specific situation,
- the space was sized by line count rather than squeezed.

A worksheet has passed the print check with question 1's work space stranded on the following page and Part 2 opening mid-page. A passing check is not evidence that the pagination is right. **After it passes, render the blank document to PDF and read it page by page** against sections 1 to 4.

## 7. Build from a builder when there is one

If the document is generated by a script, edit only the script, then rebuild. Edits made to the generated HTML (including keys, the toggle, and figure fixes) are lost on the next build. If asked to match an existing document's style, open it first and match its structure, fonts, and part panels.

## 8. Verify loop

1. Build or write the file. Run the print check on the blank state and iterate until it passes.
2. Render every page of the blank state and look at each one: overlapping labels, clipped figures, overflow, the page-structure rules above, and the rules in `diagrams.md`.
3. Fix in the builder and repeat (at most about five rounds before asking for direction).
4. Hand back with the print check's page and fill table, the page count, and confirmation that the answer-key toggle is present if the document has answers.

When output renders wrong on a target platform, simplify the markup. Never delete content (a table, a figure, a question) to make the problem go away.
